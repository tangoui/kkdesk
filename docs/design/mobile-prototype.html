kkdesk 手机端 · 设计稿

手机扫一下电脑上的二维码完成配对，之后就能在手机上远程查看、操作这台电脑。先看 ① 完整体验和 ② 模块划分，再在 ③–⑨ 每一项里点选一个方案。每项都标了「推荐」并写了理由，你可以不采纳。

手机：控制端（新做） 电脑：被控端（复用现有，补配对） 跨网：自托管 kkdesk-server 画面链路：WebRTC + H.264 硬解

配对以后，手机连电脑还要不要人确认

这一项决定安全设计和能用在哪些场景，最重要。现在电脑端用设备码连接时每次都要对方点「接受」。

好处随时随地连自己的电脑，最方便

C每台手机单独设置推荐

默认每次确认。在配对弹窗里，或之后在「已配对手机」里，可以给自己的手机打开「无需确认」。打开后手机端连接前要求 Face ID / 指纹。

好处自用电脑和帮家人看电脑都能覆盖；手机丢了还有生物识别兜底
代价比 B 多一个开关和生物识别；工作量接近 B
为什么推荐 C：A 做不到人在外面连自己的电脑，这通常是手机远程最主要的用途。B 把所有配对过的手机都当成自己的，帮别人配对时风险大。C 的长期凭据和解除配对跟 B 是同一套，只多一个开关，默认值保守，需要时再打开。

画面上有一个光标，手指在屏幕任何位置滑动都只是移动光标，和笔记本触控板一样。光标靠近边缘时画面自动跟随平移。

好处零学习成本；适合点大按钮、看文档

C两种都做，随时切换推荐

默认触控板模式，悬浮球里一键切换，按电脑分别记住上次的选择。第一次进入远程时弹一页手势说明。

好处精细操作和随手点都顺手
代价手势识别要写两套，测试量翻倍
为什么推荐 C：远程操作电脑时，大多数时候要点的是小按钮和菜单，触控板模式更准，所以作为默认。但只看看画面、点个大按钮时，直接点按更自然。主流远程软件也都两种都提供。两套手势共用同一层「触控 → 鼠标事件」转换，第二套增加的工作有限。
