# 隐私屏与锁屏设计

日期：2026-11-26
状态：用户已认可方案，待实现

## 1. 为什么做

用户两种场景都有：

1. **远程控制自己那台没人的电脑**：不希望路过的人看到屏幕上在做什么；会话结束（包括断网）后电脑不能就这么亮着、桌面没人管。
2. **远程协助别人**：对方就坐在电脑前。不能未经同意突然把对方屏幕变黑。

所以做三件事：隐私屏（被控端本地黑屏，控制端照常看到桌面并能操作）、断开后自动锁屏、控制端一键"锁屏并断开"。权限由被控端设置决定。

## 2. 目标、非目标、反目标

**目标**
- 被控端为 macOS 和 Windows（Linux 没有被控端，不涉及）。
- 隐私屏：被控端所有显示器都被黑色遮罩盖住；控制端看到的画面里没有遮罩；控制端的鼠标键盘照常作用到桌面上的应用。
- 断开后自动锁屏：被控端设置项；会话因任何原因结束（控制端断开、被控端断开、断网、超时）都锁屏。
- 锁屏并断开：控制端控制中心里的一项；锁屏后立即结束会话。
- 本次断开后锁屏：控制端控制中心里的临时开关，只影响当前会话。

**非目标**
- 禁用被控端本地键鼠（用户决定本期不做）。
- 手机控制端的入口（本期只做电脑控制端；协议要能复用，手机端之后再加）。
- 仅传文件（files-only）会话：没有屏幕共享，不提供隐私屏和锁屏选项。
- kkdesk 进程崩溃或被强制退出（SIGKILL）时保证锁屏（遮罩随进程消失；做不到可靠锁屏，文档里写明）。正常退出要锁，见 4.5；实现时注意 `Host.Close` 与应用退出的时序：先完成"先锁后撤"再停主线程事件循环，且不能在主线程上等待需要主线程执行的撤遮罩操作（死锁）。

**反目标**
- 遮罩吃掉鼠标点击或键盘焦点，导致远控无法操作。
- 遮罩出现在控制端看到的画面里（等于自己把自己黑掉）。
- 被控端用户被关在黑屏外面、没有本地退出办法。
- 会话结束时先撤遮罩再锁屏，中间露出未锁的桌面。
- 锁屏失败却告诉控制端"已锁屏"。

## 3. 现状（实现前必须读懂）

- 屏幕采集只采主显示器：`internal/capture/capture_darwin.m` 用 `SCContentFilter initWithDisplay:excludingApplications:`，`ExcludeApp` 只在本机自连时用来排除 kkdesk 自己（`captureExcludeApp`）。`internal/capture/capture_windows.cpp` 用 DXGI Desktop Duplication，`ExcludeApp` 在 Windows 上被忽略。采集可能自动重启（`internal/capture/restart.go`），重启后排除设置必须仍然生效。
- 输入注入：`internal/inject`（macOS CGEvent、Windows SendInput），坐标映射到主显示器。
- meta 数据通道已有消息：`'a'` 辅助功能、`'p'/'o'` 时钟、`'x'` 剪贴板、`0x41/0x52` 密码认证、质量、bye 等，见 `internal/session/*.go`。认证通过前 meta 消息被闸门挡住（`peer_auth.go`），新消息同样只能在认证通过、`handle` 放行后生效。
- 被控端设置：`internal/config/config.go`（如 `Confirm`），设置页 `internal/ui/settings_page.go` 的「安全」分区。
- 被控端连接确认弹窗、会话面板：`internal/ui/host_overlay.go`。
- 控制中心：`internal/ui/session_window.go` 用 Tango `sys/menu` 的 `menu.Popup` 原生菜单。
- 会话生命周期：`internal/app/host.go` 的 `handle` → `stream`，结束时 `defer` 里清理。

## 4. 方案（用户已认可）

### 4.1 被控端设置（「设置 › 安全」）

| 设置 | 选项 | 默认 |
|---|---|---|
| 隐私屏 | 不允许 / 每次询问 / 直接允许 | 每次询问 |
| 断开后自动锁屏 | 开 / 关 | 关 |

"断开后自动锁屏"旁边醒目提示："锁屏后 kkdesk 无法远程解锁，需要有人在电脑前输入密码。"（kkdesk 不能在锁屏和安全桌面下采集或注入，见 `host_windows.go` 的 `InjectLimits`。）

配置字段名、迁移由实现者定；旧配置没有这两个字段时按默认值。

### 4.2 控制中心（电脑控制端）

新增三项，仅远程控制会话（非仅查看也非传文件）显示；仅查看会话也可以用（隐私屏和锁屏不需要输入权限），由实现者按菜单现有结构决定是否在仅查看时显示，我的倾向是显示：

- **隐私屏**（勾选项）：开启时发请求；关闭时直接关。
  - 被控端设为"不允许"：控制端提示"对方不允许开启隐私屏"。
  - "每次询问"：被控端弹窗"对方请求开启隐私屏：你的屏幕会变黑，对方仍能看到并操作你的电脑。"，允许 / 拒绝，30 秒无人响应按拒绝。控制端在等待期间显示"等待对方同意…"。
  - "直接允许"：立即生效。
  - 平台不支持（如 Windows 低于 10 2004）或创建失败：提示原因，状态保持关闭。
- **本次断开后锁屏**（勾选项）：只影响当前会话，不需要对方同意（用户已认可：锁屏不泄露任何东西，对方用自己的密码即可解开）。被控端会话面板上显示"本次会话结束后将锁屏"。
- **锁屏并断开**：被控端锁屏，成功后结束会话；失败时不断开，提示"对方电脑锁屏失败：原因"。不需要对方同意。

控制中心的勾选状态以被控端回报为准（被控端拒绝或失败时，勾选要恢复）。

- 被控端用户用快捷键退出隐私屏后，本次会话内控制端再请求，一律按"每次询问"处理（即使设置是"直接允许"），否则本地用户无法真正拒绝。
- 会话中被控端把隐私屏设置改为"不允许"时，正开着的隐私屏立即关闭并通知控制端；改为其他档位不影响已开着的隐私屏。

### 4.3 隐私屏的实现

每个显示器一个无边框、全屏、纯黑、置顶的遮罩窗口，中央显示提示文字："正在被远程控制，屏幕已隐藏。按 <快捷键> 结束隐私屏"。

关键要求（两个平台都必须满足）：

1. **不被采集**：控制端画面里看不到遮罩。
   - macOS：采集过滤器排除遮罩窗口（`SCContentFilter` 的 `excludingWindows:`，通过 `SCShareableContent` 按窗口号找到对应的 `SCWindow`）。遮罩显示或撤掉时，采集过滤器要更新（`SCStream updateContentFilter:`）；采集重启后要重新带上排除。
   - Windows：`SetWindowDisplayAffinity(hwnd, WDA_EXCLUDEFROMCAPTURE)`，需要 Windows 10 2004（build 19041）及以上，DXGI Desktop Duplication 会跳过这类窗口。低版本或调用失败时，隐私屏报告"不支持"，不得退化为"遮罩出现在画面里"。
2. **鼠标穿透**：本地和注入的鼠标事件都穿过遮罩，落到下面的应用上。
   - macOS：`ignoresMouseEvents = YES`。
   - Windows：`WS_EX_LAYERED | WS_EX_TRANSPARENT | WS_EX_TOPMOST | WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE`，不透明度设为 254（不要 255，见第 8 点）。
3. **不抢焦点**：遮罩永远不成为键盘焦点窗口，不出现在任务栏、Dock、⌘Tab、Alt+Tab 里。
4. **盖住一切**：macOS 窗口层级高于菜单栏和 Dock（如 `NSScreenSaverWindowLevel`），出现在所有桌面空间和全屏应用之上（`canJoinAllSpaces | fullScreenAuxiliary | stationary`）；Windows 置顶并在其他置顶窗口变化时保持在最上面。
5. **跟随显示器变化**：显示器插拔、分辨率变化时重建或调整遮罩。
6. **本地退出**：全局快捷键结束隐私屏（我定为 macOS ⌃⌥⌘P，Windows Ctrl+Alt+Shift+P；实现者如发现冲突可换，文档同步）。macOS 用 `RegisterEventHotKey`（不需要额外权限），Windows 用 `RegisterHotKey`。只在遮罩显示期间注册。被控端用快捷键退出时通知控制端，控制端提示"对方关闭了隐私屏"。（注：控制端注入同样的组合键也会触发退出，这可以接受。）
7. **会话结束必撤**：会话因任何原因结束，遮罩都要撤掉，但顺序见 4.5。
8. **不能让下面的应用停止绘制**：全不透明的置顶全屏窗口会让下面的窗口被判为"被遮挡"，Chrome、Electron、Safari 等会暂停渲染，控制端画面会卡住。macOS 设 `opaque = NO`、alpha 略低于 1（如 0.996），Windows alpha 254。真机验收必须确认：隐私屏开启时，控制端看到的浏览器视频持续刷新。
9. **已知限制（接受，写进文档）**：Windows 的开始菜单、Alt+Tab 切换界面、通知中心、系统通知、UAC 安全桌面的层级高于普通置顶窗口，遮罩盖不住；要盖住需要 `uiAccess` 清单、代码签名和安装到受保护目录，本期不做。macOS 上遮罩能否盖住 ⌘Tab 切换器、通知、Spotlight，实现者在真机上确认并把结果写进文档。

遮罩窗口用平台原生代码实现（与 `internal/capture`、`internal/display` 一样的 cgo .m / .cpp 方式；macOS 上窗口的创建、显示、撤掉必须在主线程执行，参照 `internal/display` 的做法），放在新包里（如 `internal/privacy`），Linux 和其他平台给一个返回"不支持"的实现。

### 4.4 锁屏的实现

- Windows：`LockWorkStation()`。
- macOS：没有公开接口。用 `dlopen` 加载 `/System/Library/PrivateFrameworks/login.framework/login`，调用 `SACLockScreenImmediate`。加载或调用失败时返回错误，不要假装成功，也不要退化为只关显示器（关显示器在没开"立即要求密码"时不会锁）。必须在真机上验证锁屏确实生效（实现者在本机 macOS 上测）。
- 锁屏 API 是异步的。锁屏接口必须**等系统确认已锁**再返回成功：macOS 监听 `com.apple.screenIsLocked` 分布式通知（或轮询 `CGSessionCopyCurrentDictionary` 的 `CGSSessionScreenIsLocked`），Windows 用 `WTSRegisterSessionNotification` 收 `WTS_SESSION_LOCK`（或等效方式）。最多等 5 秒，超时按失败处理。遮罩在确认锁住之后才撤（失败或超时也撤，并报错），避免露出未锁的桌面。"锁屏并断开"的成功回报也在确认之后发出。

### 4.5 会话结束时的顺序

**何时锁**（被控端开了"断开后自动锁屏"或本次会话开了"本次断开后锁屏"时）：
- 控制端主动断开、被控端用户断开、正常退出 kkdesk（包括自动更新重启、SIGTERM）：立即锁。
- 意外断开（断网、ICE 失败、超时等，控制端没有发 bye）：先等 60 秒宽限期，期间同一被控端如有新会话通过认证并放行，则取消这次锁屏（新会话继承隐私屏状态由新会话自己请求，不自动继承）；60 秒内没有新会话则锁屏。宽限期内遮罩保持显示，被控端界面显示"连接已断开，60 秒后锁屏"倒计时，本地用户可以按退出隐私屏快捷键取消锁屏并撤遮罩。

**顺序**（`handle` 的清理路径，或宽限期结束时）：

1. 如需锁屏（被控端开了"断开后自动锁屏"，或本次会话控制端开了"本次断开后锁屏"，或这是"锁屏并断开"已经锁过则跳过）：先锁屏。
2. 再撤遮罩。
3. 再做现有的其余清理。

锁屏失败时照样撤遮罩，并在被控端界面显示错误"会话结束后锁屏失败：原因"。

### 4.6 协议

在 meta 通道新增消息（字节值、编码由实现者定，避开已用值）：

| 方向 | 消息 | 内容 |
|---|---|---|
| 控制端 → 被控端 | 隐私屏请求 | 开 / 关 |
| 被控端 → 控制端 | 隐私屏状态 | 已开 / 已关 / 对方拒绝 / 对方不允许 / 不支持（附原因）/ 被控端本地退出 |
| 控制端 → 被控端 | 本次断开后锁屏 | 开 / 关 |
| 被控端 → 控制端 | 本次断开后锁屏状态 | 开 / 关 |
| 控制端 → 被控端 | 锁屏并断开 | — |
| 被控端 → 控制端 | 锁屏结果 | 成功（随后被控端以"对方已锁屏"为原因关闭会话）/ 失败（附原因） |

- 认证通过、`handle` 放行之前收到这些消息一律忽略（沿用 v2 的闸门）。
- 仅传文件会话收到这些消息一律忽略并回"不支持"。
- 不需要兼容旧版本（v2 已经是不兼容版本，新旧版本本来就连不上）。

### 4.7 被控端界面

- 会话面板显示当前状态：隐私屏开着时显示"隐私屏已开启"；本次断开后会锁屏时显示"本次会话结束后将锁屏"。（隐私屏开着时被控端用户看不到面板，但退出隐私屏后可以看到。）
- "每次询问"的确认弹窗与现有连接确认弹窗风格一致。

## 5. 测试要求

每项先写失败测试再实现。

- Go 单元测试：宽限期（意外断开 60 秒后锁、期间新会话取消、主动断开立即锁、本地快捷键取消；用可注入的时钟）；锁屏等确认的超时；权限判定（三档 × 请求开/关）；询问超时按拒绝；会话结束顺序（用可替换的锁屏和遮罩实现，断言"先锁后撤"，锁屏失败也会撤）；files-only 会话拒绝；认证前忽略；控制端勾选状态以回报为准。
- `internal/session` 回环集成测试：新 meta 消息往返。
- 平台代码：遮罩和锁屏放在接口后面，app 层测试用假实现；平台实现至少有编译测试（`GOOS=windows` vet）和 macOS 上的冒烟测试（创建遮罩窗口、确认窗口属性：忽略鼠标、层级、不被采集——可用 `SCShareableContent` 截一帧验证遮罩不在画面里）。锁屏不在自动化测试里真正执行（会锁住测试机），macOS 锁屏由实现者手动验证一次并记录结果。
- 全部检查：`gofmt -l .` 为空、`go vet ./...`、`go test -count=1 ./...`、相关包 `-race`、`GOOS=linux CGO_ENABLED=0 go vet ./...`、`GOOS=windows` + mingw 的 vet。
- GUI 自动化测试按后台方式进行，不抢前台。
- 真机冒烟（用户或实现者）：Mac 被控开隐私屏，控制端能看到桌面并点击、输入；被控端本地黑屏且快捷键能退出；断开后自动锁屏；锁屏并断开；Windows 被控同样各项。

## 7. 我替用户做的决定（请审阅时确认）

1. 隐私屏默认"每次询问"，询问 30 秒无人响应按拒绝。
2. 本地退出快捷键：macOS ⌃⌥⌘P，Windows Ctrl+Alt+Shift+P；控制端注入同样组合键也会触发退出。
3. macOS 锁屏用私有接口 `SACLockScreenImmediate`，失败如实报错，不退化为关显示器。
4. 仅查看会话也显示隐私屏和锁屏选项。
5. 手机控制端本期不做入口。
6. 进程崩溃时不保证锁屏。
7. 被控端本地退出隐私屏后，本次会话再请求一律询问。
8. 会话中改为"不允许"立即关闭已开的隐私屏。
9. 意外断开先等 60 秒宽限期再锁屏（期间有新会话进来则取消）；主动断开和正常退出立即锁。
10. 锁屏以系统确认为准，最多等 5 秒，超时算失败。
11. 遮罩用几乎不透明（254/255）而不是全不透明，避免下面应用停止绘制。
12. Windows 开始菜单、Alt+Tab、通知、UAC 盖不住，接受并写进文档。
