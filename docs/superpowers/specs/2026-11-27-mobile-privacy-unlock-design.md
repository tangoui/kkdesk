# 手机控制端：隐私屏、锁屏、解锁与光标形状

日期：2026-11-27
状态：用户已同意（"手机端你也帮我做好"）

## 为什么

电脑控制端已有：隐私屏开关、本次断开后锁屏、锁屏并断开、解锁电脑（密码存控制端钥匙串）、对方锁屏状态提示、远程光标形状。手机控制端（`mobile/`，Flutter）一项都没有：被控端发来的这些 meta 消息被忽略，菜单里也没有入口。用户要求手机端补齐。

## 范围

只改 `mobile/`。被控端和电脑控制端的协议、行为不变，手机端按现有协议实现。两种手机会话都要覆盖：手输密码连局域网（`LanSession.connect`）和扫码配对后的会话（`connectPaired`，局域网与跨网）。

协议以 Go 实现为准（不要凭文档猜字节值）：
- `internal/session/privacy.go`（隐私屏请求/状态、本次断开后锁屏、锁屏并断开及结果）
- `internal/session/lockscreen.go`（锁屏状态、解锁请求与结果）
- `internal/session/cursor.go`（光标形状 `0x9b`）
- 认证通过前不发送、不处理（手机端已有 `_LanPasswordExchange` 闸门；配对会话按其现有就绪逻辑）。

## 功能

1. **远控菜单**（`mobile/lib/ui/remote.dart` 现有菜单）新增：隐私屏（开关，状态以被控端回报为准，等待同意时显示"等待对方同意…"）、本次断开后锁屏（开关）、锁屏并断开、解锁电脑（仅在被控端回报已锁屏时出现；仅查看时不显示）。仅传文件会话不显示这些项。
2. **锁屏状态提示**：被控端回报的锁屏状态在会话界面显示，文案与电脑端一致（`internal/ui/unlock.go` 的 `lockScreenReason`，以及最新的细分原因：未安装、未从安装位置运行、服务未运行、需要更新、需要正式签名、平台不支持、其他错误）。
3. **解锁电脑**：
   - 未保存密码：弹框输入"对方电脑的登录密码或 PIN"，可勾选"记住密码"（默认不勾）。
   - 已保存：先做**面容/指纹验证**（`local_auth`，已在依赖里），通过后直接提交；验证失败或取消则不提交。设备没有生物识别时退回系统设备密码验证；都不可用时不允许保存密码（只能每次手输）。
   - 保存在 `flutter_secure_storage`（已在依赖里），iOS 钥匙串 / Android 密钥库，**按被控端公钥**区分（配对会话用配对时的电脑公钥；手输密码局域网会话用认证 v2 记住的局域网身份公钥）。不按地址或设备码。
   - 解锁结果：成功、密码可能不正确（已保存的密码时提示"已保存的解锁密码不正确"并提供重新输入/忘记）、不支持、尝试过多。提供"忘记解锁密码"。
   - 密码不写日志；内存中用完尽量清除。
4. **光标形状**：触控板模式下手机画的指针改为对方的形状（箭头、小手、文本竖线、禁止、左右/上下调整、移动、抓取、抓取中），未知形状用箭头。直接点按模式不画指针，不需要处理。可以用 Flutter 自带的图标或简单自绘，风格与现有指针一致。

## 测试

- Dart 单元测试：各 meta 消息的编解码与 Go 一致（尽量与 Go 测试共用固定字节样例）；认证前忽略；仅查看/传文件不显示入口；锁屏状态文案映射；解锁流程（未保存、已保存+生物识别通过/失败、密码错误、尝试过多）；按公钥存取与忘记（用 flutter_secure_storage 的测试替身）。
- Widget 测试：远控菜单项随状态显示/隐藏。

## 我替用户做的决定

1. 已保存的解锁密码在提交前必须通过面容/指纹（或设备密码）验证；都不可用时不提供"记住密码"。
2. 按被控端公钥保存。
3. 与电脑端一致：仅查看不显示解锁；传文件会话不显示这些项。
4. 光标形状只在触控板模式生效。
