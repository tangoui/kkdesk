# 常见问题

## 一直提示「端口被系统保留」

Windows 上装了 Hyper-V、WSL 或 Docker 时，系统会整段保留端口（一段往往 100 个以上）。新版 kkdesk 会自动换一个系统分配的空闲端口并保存为默认端口，下次启动不会再提示。仍然有问题时，用下面的命令查看保留范围，在「设置 › 局域网」里填一个范围外的端口：

```powershell
netsh interface ipv4 show excludedportrange protocol=tcp
```

## 提示「网络不通，两台电脑可能不在同一个局域网」

控制端根本走不到对方的地址（系统报 `no route to host`）。常见原因：

- 两台电脑接在不同的路由器下，例如一台接主路由、一台接二级路由；
- 一台连的是访客 Wi-Fi，或者用的是手机热点；
- 两台电脑其实在不同的地方。

看一下两边的本机地址：前三段不同（例如 `192.168.1.x` 和 `192.168.3.x`）通常就是这个问题。把两台接到同一个路由器或 Wi-Fi，或者改用 [跨网连接](./remote)。

## 连接超时

- 被控端的防火墙拦截了连接：Windows 上在防火墙里允许 kkdesk（专用网络，必要时也勾上公用网络）。
- 两台电脑不在同一张网络里：从一边 `ping` 另一边的地址试试，不通就不是 kkdesk 的问题。
- 被控端在二级路由或运营商的 NAT 后面：外面的电脑访问不到它的私网地址，只能用 [跨网连接](./remote)。

## 本机地址里有一个连不上的 192.168.x.1

那多半是 Hyper-V、WSL、Docker 或虚拟机的虚拟网卡，别的电脑访问不到。kkdesk 会把实际上网用的地址排在第一个，把虚拟网卡排在最后，请把第一个地址告诉对方。

## 对方能看到画面，但操作没反应

- 被控端是 macOS：需要「辅助功能」权限。
- 控制端处于「仅查看」：在控制中心取消勾选「仅查看」。
- 连接的是本机自己：自连会强制仅查看。
- 被控端是 Windows 且对方在操作管理员窗口或 UAC 弹窗：以普通权限运行的 kkdesk 操作不了它们。

## 用 tan dev 运行时，屏幕录制权限怎么给

开发时权限记在启动 `tan dev` 的终端应用上，请在「系统设置 › 隐私与安全性 › 录屏与系统录音」和「辅助功能」里给这个终端应用开权限，然后重启终端。

## 画面帧率只有 30 fps 左右

在同一台 Mac 上自连时，系统要同时合成被采集的画面和显示远端画面，屏幕采集会被降频，所以只有约 30 fps。两台电脑之间连接时才能看到真实帧率。

## 剪贴板没有同步

- 被控端是否关掉了「剪贴板」权限；
- 控制端是否处于「仅查看」，或者用的是「传文件」方式；
- 复制的是不是图片或文件（目前只同步文字）。

## 反馈问题时附什么

- 被控端的自检结果：`kkdesk -selftest` 生成的 `kkdesk-selftest.log`；
- 问题界面的截图；
- 两边的系统版本，以及是局域网还是跨网连接。
